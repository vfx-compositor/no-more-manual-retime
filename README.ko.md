# No More Manual Retime

[English](README.md) · **한국어** · [소개 페이지](https://vfx-compositor.github.io/no-more-manual-retime/) · [Nukepedia](https://www.nukepedia.com/tools/python/misc/no-more-manual-retime-auto-retime-matching/)

No More Manual Retime은 Nuke 안에서 편집본 리타임과 플레이트를 매치시킵니다. 오프라인 편집본과 원본 카메라 플레이트를 주면, 편집본의 각 프레임이 플레이트의 어느 프레임인지 찾아 TimeWarp, 맞는 리프레임, QC 노드 세트를 만들어 줍니다.

EDL, XML, 일치하는 타임코드가 필요 없습니다. 실제로 받는 오프라인 편집본, 즉 색보정되고 압축되고 리프레임되고 번인이 덮인 영상을 대상으로 만들었습니다.

결과는 하나의 TimeWarp 노드입니다. 샷 안의 컷처럼 속도로 설명되지 않는 변화는 경고로 알려 줍니다.

| | |
|---|---|
| 입력 | 오프라인 편집본, 카메라 플레이트 |
| 생성 | TimeWarp, 리프레임(Transform), QC 노드 세트, 리포트 노트 |
| 실행 환경 | GUI가 있는 Nuke 15.1 이상, numpy |
| 라이선스 | MIT |

**처리는 전부 로컬입니다.** 분석과 번인 타임코드 인식은 내 컴퓨터에서 numpy로 처리합니다. 신경망, 모델 다운로드, 업로드, API 키가 없습니다. 원본 미디어는 읽기만 하며 이름 변경, 이동, 덮어쓰기를 하지 않습니다.

## 1.1.0에서 바뀐 것

리타임 결과는 1.0.2와 같습니다. 288회 재생 비교(144조건, 이미지만과 이미지 + 번인 TC)에서 모든 편집 프레임이 같은 플레이트 프레임과 같은 TimeWarp 그래프를 받았습니다. 컷이 없는 곳의 거짓 컷 경고는 줄었고 진짜 컷 경고는 그대로입니다(정답 컷 42회 측정). 바뀐 것은 결과 주변 도구와 일부 기본값입니다.

**바뀐 기본값과 출력 노드 구성 (업그레이드 전에 확인)**

- **리프레임 출력 (Beta)** 이 기본으로 켜집니다. 이전 버전에서 저장한 값이 있으면 그 값을 따릅니다.
- **기존 Write 설정 따르기** 가 기본으로 켜집니다. QC 리뷰 Write가 스크립트에 있는 Write의 코덱·품질·채널을 따릅니다. 색공간은 출력·디스플레이 계열(sRGB, Rec.709 등)일 때만 따르고 log·linear는 따르지 않습니다. 끄면 1.0.2의 고정 설정입니다.
- **결과 블록이 한 줄로 이어집니다.** 플레이트마다 노드가 TimeWarp, FrameRange, 맞춤, 옵티컬, Difference, MP 라벨, 끝 Dot 순서로 이어지고 편집본 노드는 그 왼쪽에 있습니다. `NMMR_timecode` 노드는 더 만들지 않습니다. 플레이트 TC(MP) 라벨은 QC 갈래에만 있고 기본으로 켜집니다.
- **QC 리뷰 출력** 은 스크립트 옆 `retime_QC_reviews/` 에 저장됩니다(이전 `qc_review/`). 샷마다 Group 하나이고 모든 Group이 AppendClip 하나와 Write 하나로 이어집니다.
- **언어 선택** 이 창 머리글에서 **설정** 창 맨 위로 옮겨졌습니다(톱니 버튼, macOS Cmd+, / Windows·Linux Ctrl+,).

**새 기능**

- 번인 TC **TC만** 모드: 믿을 만한 번인 TC로 이미지 매칭 없이 타이밍을 정합니다. 합성 번인 144조건 중 83조건을 받아들였고 그 조건에서 99.4% 정확했으며 분석 시간은 기본 모드의 절반 이하였습니다(합계 539.8초 대 1,194.3초). TC만은 이미지 매칭을 건너뛰어 빠릅니다. 정지 화면이나 암전처럼 이미지로 프레임을 가리기 어려운 구간도 번인 TC만 읽히면 그 TC로 플레이트 프레임을 정합니다. 긴 구멍·오독·플레이트 TC 없음은 추측하지 않고 거절합니다.
- **QC 렌더 방식:** Nuke에서 바로 렌더하거나 렌더팜용으로 Write 노드만 만듭니다. 형식은 고른 그대로(MOV 또는 JPEG)입니다.
- **분할합성 (Beta):** 영역을 그리면 맞는 플레이트를 자동으로 고릅니다. 한 화면에 두 클립이 있는 구간을 컷이 아니라 합성으로 보고합니다.
- **Difference 배치** 옵션(B 파이프 또는 옆 가지)과 배치 결과 배치 옵션.
- **진행 표시:** 긴 Nuke 호출 중에도 막대가 움직이고 멈추면 `마지막 진행 n초 전`을 보여 줍니다.
- **MP 라벨 Group 하나:** 플레이트 TC(MP) 라벨이 Group 하나이고 위치·크기·불투명도·굵기·색 노브가 있습니다. 직접 지정 위치에서는 Viewer에 Transform 핸들이 나옵니다.
- **실행이 끝나면 항상 창 하나:** 끝까지 돈 실행은 창이 하나 뜹니다. 단일 실행은 완료 헤드라인과 QC 리뷰 결과를 보여 주고 경고는 같은 창의 헤드라인 아래에 이어집니다. 배치는 끝에 한 번 성공·확인 필요·건너뜀·실패 샷 수를 보여 줍니다. 취소한 실행에는 완료 창이 없습니다.

**수정**

- QC 화면의 MP TC(플레이트 TC 표시)가 램프·역재생·정지 구간에서도 실제로 쓰인 플레이트 프레임의 TC를 보여 줍니다. 예전에는 속도가 일정하다고 보고 계산해서 이런 구간에서 TC가 틀리게 나왔습니다.
- OCIO 프로젝트에서 QC 리뷰 Write가 `Invalid LUT selected`로 멈추지 않습니다.
- 큰 스크립트: 분석 중 임시 노드를 덜 만듭니다.
- QC 리뷰를 같은 분에 두 번 실행해도 앞선 결과를 가리키지 않습니다. 두 번째 폴더에는 `_2`, 그다음은 `_3`처럼 붙여 덮어쓰지 않습니다.
- 처음 실행할 때 언어가 OS 표시 언어를 따릅니다(OS가 한국어면 한국어 그 밖은 영어). Nuke를 `LANG` 설정 없이 켜도 같습니다. **설정**에서 고른 언어가 있으면 그 값이 우선입니다.
- Nuke 15.1에서 창이 열리지 않던 문제를 고쳤습니다.
- 창을 연 채 다른 스크립트를 열면 이전 스크립트의 배치 행과 완료 문구가 남던 문제를 고쳤습니다.
- 같은 분에 QC를 Write 노드만 두 번 만들면 두 Write가 같은 경로를 쓰던 문제를 고쳤습니다. 두 번째에는 `_2`가 붙습니다.
- 실행 중에는 EDIT·PLATE 선택과 새로고침이 잠깁니다. 분석 도중 소스가 바뀌지 않습니다.
- 배치를 실행하는 동안 **편집본 다시 찾기**와 **행 제거**를 누를 수 있어 표가 실행과 어긋나던 문제를 고쳤습니다. 실행이 끝날 때까지 배치 도구 버튼이 잠깁니다.
- QC 리뷰 렌더가 권한이나 디스크 문제로 실패해도 '취소'로만 표시되던 문제를 고쳤습니다. 이제 실패와 이유를 보여 줍니다.

## 설치

설치 없이 바로 실행하거나, 메뉴 명령으로 등록할 수 있습니다.

**한 번만 써 보기 (Script Editor).** Nuke에서 Script Editor 패널을 열고, 아래 Python 입력 영역에 `no_more_manual_retime.py` 전체를 붙여넣은 뒤 macOS는 Cmd+Enter, Windows와 Linux는 Ctrl+Enter로 실행합니다.

**메뉴 명령 등록**

1. 개인 `.nuke` 폴더 안의 `python` 폴더(없으면 만들기)에 `no_more_manual_retime.py`를 넣습니다.
2. `~/.nuke/menu.py` 끝에 아래를 추가합니다(파일이 없으면 새로 만들고, 기존 내용을 덮어쓰지 마세요).

```python
import nuke

nuke.pluginAddPath("./python")
import no_more_manual_retime

nuke.menu('Nuke').addCommand('NMMR/No More Manual Retime', 'no_more_manual_retime.run()', 'ctrl+alt+r')
nuke.menu('Nuke').addCommand('NMMR/No More Manual Retime (Batch Selected)', 'no_more_manual_retime.run_batch_selected()')
```

3. Nuke를 다시 시작하면 메뉴 막대에 **NMMR > No More Manual Retime**이 나타납니다.

`ctrl+alt+r`은 macOS에서 Cmd+Option+R입니다. 이미 쓰는 단축키라면 다른 키로 바꾸세요.

### numpy

Nuke에는 numpy가 들어 있지 않습니다. 없으면 첫 실행 때 설치 창이 열리고, 설치 뒤 Nuke를 다시 시작할 필요가 없습니다. 방법은 세 가지입니다.

- **오프라인:** 플랫폼에 맞는 numpy 휠을 스크립트 옆 `vendor/` 폴더에 두거나 창에서 폴더를 지정합니다.
- **온라인:** **온라인 설치 (pip)** 를 누르면 Nuke 내장 Python으로 `pip install --target`을 실행해 Nuke 설정 밖의 `~/.nuke_pylibs/`에 설치합니다.
- **공용 폴더:** 환경변수 `NMMR_NUMPY_PATH`로 모든 워크스테이션이 같은 numpy 폴더를 보게 합니다.

Nuke 16 미만은 Python 3.10, Nuke 16 이상은 Python 3.11을 쓰므로 맞는 휠을 받으세요. 예:

```bash
pip download numpy --only-binary=:all: --no-deps -d vendor --python-version 3.11 --platform macosx_14_0_arm64
```

## 사용

1. 편집본과 플레이트를 Read 노드로 스크립트에 불러옵니다.
2. 둘을 선택한 채(선택 사항) **NMMR > No More Manual Retime**을 실행합니다.
3. **EDIT**이 편집본, **PLATE**가 원본 소스인지 확인합니다. **First Frame** 기본값은 **Plate 시작**입니다.
4. **실행**을 누릅니다.

플레이트 옆에 TimeWarp, FrameRange, 플레이트를 편집본 포맷으로 맞추는 Reformat과 Transform, QC 노드 세트(편집본과 리타임한 플레이트 비교), 리포트 노트가 만들어집니다. 한 번의 실행으로 만든 노드는 한 백드롭 안에 모이며 Ctrl+Z 한 번(macOS는 Cmd+Z)으로 되돌립니다.

플레이트 Read 여러 개를 선택하고 **NMMR > No More Manual Retime (Batch Selected)** 를 쓰면 차례로 처리합니다.

### 결과 읽기

플레이트마다 0–100%의 **일치도**가 나옵니다. 약 85% 이상이면 좋음(QC 노드 세트를 훑어 확인), 70–85%는 보통(리포트에 적힌 프레임 근처의 QC 차이를 확인), 그 아래는 리포트에 *확인 필요*가 표시됩니다. 일치도는 **분절컷 의심** 표시와 별개이며, 잘 맞는 샷에도 분절컷 의심이 하나 있을 수 있습니다.

### 어려운 구간 고치기

타임라인을 불러오면 편집본이 필름스트립으로 보입니다. 구간을 **배제**(타임코드나 등속으로 채움)하거나, 프레임에 **고정점**을 두어 그 지점에서 EDIT = PLATE로 강제할 수 있습니다. 직접 입력도 됩니다. 예: 배제 `1005-1012, 1030`, 고정점 `1020=1088, 1040=1102`.

오프라인에 소스 타임코드 번인이 있으면 **TC 보정…**으로 외부 OCR 없이 읽어 힌트로 씁니다. 타임코드는 힌트일 뿐이며 판단은 화면이 합니다.

## 다루는 것

- 등속, 오프셋, 램프, 홀드, 역재생을 플레이트 정수 프레임으로 기록합니다(기본 편집본 프레임당 플레이트 최대 16프레임, 4–16으로 설정 가능. 8× 이상은 측정 사례가 적습니다).
- 색보정되거나 LUT가 구워진 편집본: 랭크 정규화 휘도로 매칭합니다.
- 리프레임: 스케일, 위치, 플롭, 샷 도중 변하는 줌까지.
- 번인, 로고, 워터마크를 자동으로 잘라내고 마스킹합니다.
- 보간으로 만든 슬로우 모션(프레임 블렌드, 옵티컬 플로우): 편집 프레임마다 소수 플레이트 위치를 구하고 TimeWarp가 그 룩업을 담습니다.
- 화면으로는 프레임을 구분할 수 없는 거의 정지한 구간: 경고하고 등속 직선으로 잇습니다.
- 여러 샷 일괄 처리, 분할합성 샷(Beta, 검증 범위 제한).
- 모든 결과를 한 영상이나 JPEG 시퀀스로 이어 붙이는 QC 리뷰 렌더(선택).

## 한계

- 회전은 감지하지 않습니다. 회전 구간은 배제하거나 고정점을 두세요.
- 0.8–1.6× 밖의 스케일은 탐색하지 않습니다.
- 리타임은 플레이트 정수 프레임이며, 보간 슬로우 구간만 TimeWarp가 소수 룩업을 담습니다. 기본 출력은 두 플레이트 프레임 중 앞 프레임을 렌더합니다.
- 보간(Kronos 등)으로 만든 슬로우 모션은 아직 약하고, 줌과 겹치면 더 약합니다.
- QC 렌더는 톤 차이는 무시하지만 전부는 아닙니다. 편집본에만 있는 번인은 정확한 리타임에서도 희미한 밝은 윤곽을 남깁니다. 크고 구조적인 번쩍임을 기준으로 판단하세요.
- OCIO·ACES 프로젝트에서는 편집본과 플레이트 Read의 색공간을 직접 지정하세요. 기본값으로 두면 멈추거나 이미지 분석 정확도가 떨어질 수 있습니다. 태그 없는 ProRes 편집본도 색공간을 직접 지정하세요.
- 플레이트 TC(MP) 라벨은 QC 갈래에만 그립니다. TimeWarp 출력에는 번인이 없습니다.
- 샷 안에서 프레임을 잘라낸 곳은 따라 뛰지 않고 경고합니다. 2–3프레임 점프는 경고가 나오지 않고, 실제 촬영분에서는 읽을 수 있는 타임코드가 없을 때 4·8프레임 점프도 경고가 나오지 않았습니다.
- macOS의 Nuke 16.1에서 검증했습니다. macOS Nuke 15.1v8에서는 창 열기, 단일 실행, QC 렌더를 확인했습니다(2026-11-10). Windows와 Linux는 실제 Nuke에서 아직 검증하지 않았습니다.

## 정확도

개발에 쓰지 않은 샷 16개의 편집 조건 144개(모드당 12,504프레임, 버전 1.0.1·1.0.2·1.1.0과 같은 매칭 결과)로 측정했습니다. 실제 Nuke 썸네일 캐시를 CPU에서 재생한 값이며 GUI 렌더가 아닙니다. 번인 타임코드는 테스트용으로 생성한 번인이며 실제 촬영본에서 읽은 값이 아닙니다. 실패 조건을 모두 포함했고, 저움직임·암전 샷이 가장 약합니다.

| 경우 | 조건 | 이미지만 | 이미지 + 번인 TC | 98% 이상 조건 (이미지 / TC) |
|---|---:|---:|---:|---:|
| 일반 리타임 (0.5×, 1×, 2×, 램프, 홀드, 역재생) | 102 | 97.35% | 99.87% | 90/102 / 100/102 |
| 리프레임 | 34 | 92.59% | 99.80% | 25/34 / 33/34 |
| 4×/8× (별도 보고) | 8 | 90.10% | 100.00% | 7/8 / 8/8 |

정확도는 TimeWarp가 정답과 똑같은 플레이트 프레임을 낸 프레임 비율입니다. ±1프레임 이내는 일반 99.01% / 99.91%, 리프레임 95.34% / 100.00%, 4×/8× 90.62% / 100.00%입니다.

## 선택: 경로 설정

기본적으로 도구는 스크립트의 Read 노드를 씁니다. 샷이 일정한 폴더 구조를 따른다면 창 머리글의 톱니 버튼으로 **설정** 창(맨 위 언어, 그 아래 경로 설정)을 열어 구조를 한 번 설명하면, 작업 중인 샷의 최신 플레이트와 편집본을 찾아 줍니다. 설정은 `~/.nuke/no_more_manual_retime_paths.json`에 저장되며, 공용 파일은 `NMMR_PATHS`로 지정합니다. 첫 실행 언어는 `NMMR_LANGUAGE=ko` 또는 `en`으로 정합니다.
